# Архитектурное дополнение: статусы наполнения

Статус документа: правила для последующей реализации. Код приложения не изменён.
Основной источник требований — `../ТЗ_сметное_дело.md`; уточнения пользователя имеют приоритет.

## Область расчёта

Для каждой пары «регион + структурный узел» (процесс, блок или операция) обязательна собственная запись `RegionalNodeContent` с `definition: 'not-defined' | 'defined'`.

Прямой каталог узла включает только документные позиции, у которых `owner` указывает на этот узел, а `regionId` совпадает с выбранным регионом. Материалы принадлежат документной позиции и наследуют её регион. Документы и материалы дочерних узлов в прямые показатели не включаются.

Обозначения:

- `D` — количество непосредственных документных позиций выбранного региона.
- `T` — общее количество зарегистрированных материалов этих позиций, включая материалы без ссылки.
- `A` — количество материалов с допустимой ссылкой.
- `U` — количество непосредственных документных позиций без единого зарегистрированного материала.

Документная позиция без материалов учитывается в `D` и `U`, но не создаёт фиктивный материал для знаменателя `T`. Подсчёт выполняется по уникальным ID материалов после проверки целостности данных.

## Таблица правил

Правила применяются сверху вниз. Ошибки структуры имеют приоритет над вычислением пользовательского статуса.

| Условие | Результат | Отображение |
| --- | --- | --- |
| Обязательная региональная запись отсутствует или дублируется | Ошибка структуры данных | Сообщение о невозможности получить корректные данные раздела; автоматический статус не назначается |
| `not-defined` и `D > 0` | Ошибка противоречивых данных | Статус наполнения не вычисляется до исправления противоречия |
| `not-defined` и `D = 0` | Состав не определён | «Состав документов и материалов ещё не определён» |
| `defined` и `D = 0` | На данном уровне документов нет | «Документы непосредственно на этом уровне не размещены»; дочерние разделы остаются доступны |
| `defined`, `D > 0`, `A = 0` | Документы определены, файлы отсутствуют | «Документы определены, файлы пока не загружены или ссылки недоступны» |
| `defined`, `D > 0`, `A > 0`, при этом `A < T` или `U > 0` | Частичное наполнение | «Доступно A из T материалов»; при `U > 0` дополнительно «Документных позиций без материалов: U» |
| `defined`, `D > 0`, `T > 0`, `A = T`, `U = 0` | Прямой каталог полностью наполнен | «Все материалы доступны: A из T» |

Если у одной позиции все материалы доступны, а у другой нет ни одного материала, раздел остаётся частично наполненным. Даже при `A = T` дополнительно показывается `U`; равенство счётчиков само по себе не означает полноту.

Полнота определяется относительно явно определённого состава данных, а не предполагаемого перечня будущих файлов. Неизвестный состав нельзя считать полным.

## Ссылка и доступность

Материал считается доступным для действия «Открыть» только при наличии непустого URL, прошедшего проверку допустимости. Пустое значение, `#`, синтаксически некорректный адрес, запрещённая схема и адрес-заглушка доступными не считаются.

Синтаксическая проверка URL не доказывает существование файла или наличие прав Google Drive. Реальные ссылки проверяются при наполнении. Если проверкой подтверждена неработоспособность ссылки, такой материал не включается в `A` и действие открытия для него не показывается; результат проверки должен быть доступен слою расчёта. Без механизма проверки нельзя сообщать пользователю, что доступ к файлу подтверждён.

Количество `A`, `T`, `D`, `U` и итоговый статус вычисляются из данных. Они не редактируются вручную и не хранятся как независимый источник истины.

## Прямое и вложенное наполнение

Прямой статус относится только к текущему владельцу документов. Сообщение об отсутствии прямых документов не заменяется сообщением об отсутствии материалов во всём процессе.

Сводка по потомкам, если отображается, рассчитывается отдельно и подписывается «Во вложенных разделах». Доступные материалы потомков не превращают прямой каталог в наполненный; отсутствие материалов у потомков не меняет полноту прямого каталога.

Нельзя называть всё поддерево полностью наполненным только на основании прямого статуса. При необходимости такой сводки проверяется каждый узел поддерева: обязательные записи корректны, нет `not-defined`, нет частичных или ожидающих файлов каталогов. Узел `defined` без прямых документов допустим и не считается пробелом наполнения.

## Проверки противоречий и регионов

1. Для каждой пары «настроенный регион + структурный узел» существует ровно одна запись наполнения с допустимым `definition`.
2. При `not-defined` прямые документные позиции запрещены. Ограничение не распространяется на документы самостоятельных дочерних узлов.
3. У каждого документа существуют владелец и регион; каждый материал связан с существующим документом. Дубли ID и осиротевшие материалы — ошибки структуры.
4. Документный ID запрашивается совместно с регионом. Материал другого региона не отображается и не открывается как материал текущего каталога.
5. При отсутствии региональных документов запрещена подстановка другого каталога. Отсутствие обязательной региональной записи не маскируется пустым массивом.
6. При смене региона отменяется либо игнорируется устаревший ответ. Данные предыдущего региона не показываются под новым региональным заголовком даже на время загрузки.
7. Действие открытия отсутствует у материала без допустимой ссылки. Недоступная карточка может оставаться видимой с пояснением.
8. Состояния загрузки и ошибки запроса не являются статусами наполнения. «Не загружено» в техническом смысле не означает «файлы отсутствуют».

## Проверочные сценарии

| № | Исходные данные или действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | `not-defined`, `D = 0` | Сообщение о неопределённом составе; нет вымышленных карточек |
| 2 | `not-defined`, `D = 1` | Валидатор сообщает противоречие; статус не присваивается |
| 3 | `defined`, `D = 2`, `T = 0` | Документы показаны, файлы отсутствуют; `U = 2`; нет открытия |
| 4 | `defined`, `D = 1`, `T = 3`, у всех материалов пустые либо недопустимые ссылки | `A = 0`; состояние отсутствия доступных файлов; нет открытия |
| 5 | `defined`, `D = 1`, `T = 3`, две допустимые ссылки | Частичное наполнение; «Доступно 2 из 3 материалов»; открываются только два материала |
| 6 | `defined`, `D = 2`, у каждой позиции есть материалы, все три ссылки допустимы | `A = T = 3`, `U = 0`; прямой каталог полностью наполнен |
| 7 | `defined`, `D = 2`, у первой позиции два доступных материала, у второй материалов нет | Частичное наполнение; «Доступно 2 из 2 материалов» и «Документных позиций без материалов: 1»; нет заявления о полноте |
| 8 | `defined`, прямых документов нет, в дочернем блоке есть доступные материалы | Сообщение об отсутствии документов на данном уровне; дочерний блок доступен; его материалы учитываются только в отдельной сводке |
| 9 | Прямой каталог полон, дочерний блок `not-defined` | Прямой каталог показан как полный; всё поддерево полным не объявляется |
| 10 | `not-defined` у процесса без прямых документов, у дочернего блока есть документы | Нет противоречия прямого каталога; статусы обоих уровней независимы |
| 11 | Региональная запись узла отсутствует | Ошибка структуры; нет автоматического `not-defined` или `defined` |
| 12 | У одной пары «регион + узел» две записи либо недопустимое значение `definition` | Ошибка структуры |
| 13 | В Москве документы есть, в регионах корректная запись `defined`, документов нет | В регионах показано отсутствие прямых документов; московские данные не подставляются |
| 14 | Открыть московский документ с выбранным регионом `regions` | Документ не выдаётся как региональный; понятное сообщение и переход к структурному владельцу |
| 15 | Быстро переключить регион, старый запрос завершился позже нового | Устаревший результат игнорируется; чужие материалы не появляются |
| 16 | Удалить ссылку одного из трёх доступных материалов | `A` автоматически меняется с 3 на 2; статус становится частичным; действие открытия исчезает |
| 17 | Добавить материал без ссылки к полному каталогу | `T` увеличивается, `A` прежнее; статус становится частичным |
| 18 | Добавить документную позицию без материалов к полному каталогу | `U` увеличивается; статус становится частичным даже при `A = T` |
| 19 | Подтверждена неработоспособность ранее допустимой ссылки | Материал исключён из `A`; действие открытия недоступно; статус пересчитан |
| 20 | Осиротевший материал, неизвестный владелец или дублирующийся ID | Ошибка целостности; не считать данные корректным наполнением |
| 21 | Запрос ещё загружается или завершился ошибкой | Состояние загрузки либо ошибки; не показывать вычисленное «файлы отсутствуют» из пустого временного результата |

## Дополнение к плану реализации

- Этап типов и валидации: закрепить обязательность региональных записей, родительские связи и запрет `not-defined` с документами; проверить сценарии 1–2, 10–12, 20.
- Этап региональных каталогов и статусов: реализовать единый расчёт `D`, `T`, `A`, `U`; проверить сценарии 3–9, 16–19.
- Этап репозитория: обеспечить изоляцию регионов и корректную обработку загрузки; проверить сценарии 13–15, 21.
- Этап интерфейса документов: отобразить все состояния таблицы, частичность и отсутствие действия открытия; использовать результаты расчёта, а не собственные счётчики компонентов.
- Итоговая приёмка: повторить все сценарии; отдельно проверить независимость прямого каталога и поддерева. Это план будущих проверок, а не отчёт об уже выполненном тестировании приложения.

Реализация выполняется только после подтверждения пользователя.
